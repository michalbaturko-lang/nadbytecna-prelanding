# Manual email AI pilot — 12 November 2026

Completed two real API runs over the same 12 deliberately selected Inbox threads, plus two explicitly synthetic legal-help controls. Initial model: gpt-4o-mini. Candidate: gpt-5.6-terra with low reasoning effort. Prompts and classification schema were kept the same. Results are illustrative, not a random sample or a measured production accuracy rate.

The first run returned 10 of 12 real-email results and two errors. Candidate returned all 12. Candidate improved newsletter, internal web proposal, PR sales and media-query routing, and requested human verification of a payout-account change.

Remaining gaps: one primary subtype cannot represent a personal story plus an offer; professional CVs are misleadingly labelled personal stories; an e-shop shipping question was routed as a community help request; spam must have an application-enforced human-review requirement rather than relying on model confidence. The synthetic legal-help controls do not validate this category on genuine project help requests; no unequivocal real example was identified in the selected sample.

Automatic AI remained disabled. Pilot classification is read-only: no classifier-save, label, status or reply operation. The sampled production classification fields were compared before and after and were unchanged. User-facing local report and the unmodified JSON outputs are outside this public repository; do not commit real message text, subject lines or IDs.

Important: the normal worker still defaults to gpt-4o-mini. The candidate was selected ONLY through the expiring server-side AI_EMAIL_PILOT_SAMPLE config. Enabling the automation flag alone would not adopt the tested candidate. Before any adoption, resolve routing/review gaps and deliberately choose the production model, then seek the user's explicit automation approval.

18 focused classification, pilot authorization, expiry, revocation, stale-source and API tests passed. Pilot test route requires an authenticated administrator, confirmation marker and an unexpired allowlist of at most 16 thread IDs. Source-specific AI revocation remains effective. The UI clearly separates real mail from synthetic controls and supports local JSON export.
